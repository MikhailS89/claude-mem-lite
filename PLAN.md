# План: безопасный локальный аналог claude-mem для Claude Code

> Составлено на основе изучения исходного кода `github.com/thedotmack/claude-mem`
> (клонирован и прочитан напрямую: `hooks.json`, `src/hooks/hook-response.ts`,
> `src/storage/sqlite/schema.ts`, `src/server/mcp/recall-mcp-server.ts` и структура
> репозитория). Документ передаётся в другую консоль (Claude Opus 5) как
> самостоятельное ТЗ — не требует контекста этого разговора.

---

## 0. Что оказалось в оригинале (и почему мы НЕ копируем это 1:1)

Реальный claude-mem — не маленький плагин, а production-платформа:
worker-процесс на Bun (HTTP API), MCP-сервер, SQLite (FTS5) + опционально
Postgres, таблицы `teams`/`team_members`/`api_keys`/`audit_log` (мульти-тенантность),
векторный поиск через Chroma, облачный "observer"-сервис с логином и подпиской,
40+ built-in скиллов, поддержка 8 разных агентов (Claude Code, Codex, Cursor,
Grok Bot, OpenClaw и т.д.), обфусцированные bash-хуки на 2000+ символов в одну
строку. Это результат года+ разработки одного человека и комьюнити.

**Решение:** строим свой аналог с той же *идеей* (память между сессиями Claude
Code, автоматический захват + сжатие + возврат контекста), но:
- только локально (без облачного аккаунта/подписки/токена по умолчанию);
- только SQLite (без Postgres/Chroma на первом этапе);
- без multi-tenant слоя (teams/api_keys/audit_log) — это персональный инструмент;
- без исполнения обфусцированного шелл-кода — обычные читаемые Node/TS-скрипты;
- с явными настройками приватности и включением/выключением каждого хука.

## 1. Архитектура (核心 core loop)

```
Claude Code hooks (SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd)
        │
        ▼
  Node-скрипт-обработчик хука (packages/hooks/*.mjs)
        │  пишет "сырые" события
        ▼
  SQLite (better-sqlite3), один файл на машину или на проект
   - raw_events      (что произошло: инструмент, файл, diff, промпт)
   - observations    (сжатые по одному событию заметки — опционально)
   - summaries       (сжатие по окончании сессии, дороже по токенам)
        │
        ▼ (по запросу, не автоматически на каждый промпт)
  MCP-сервер (stdio) с инструментами search / recent / get
        │
        ▼
  SessionStart / UserPromptSubmit хук инжектит ТОЛЬКО краткую сводку
  (не полный дамп истории) в контекст новой сессии
```

Ключевое архитектурное решение оригинала, которое стоит перенять —
**progressive disclosure**: сначала лёгкий индекс (~50-100 токенов/результат),
потом по явному запросу — полные детали (~500-1000 токенов/результат).
Это и есть источник настоящей экономии токенов, а не магия.

## 2. MVP: минимальный набор функций (этап 1)

Цель этапа — рабочий плагин, который реально экономит время на 1 машине,
без сети и без LLM-суммаризации.

1. **Хуки:**
   - `SessionStart` — читает последние N записей из SQLite для текущего
     проекта (по `root_path` / git remote как идентификатору проекта) и
     возвращает `additionalContext` (короткая сводка, не сырой лог).
   - `PostToolUse` — логирует факт использования инструмента (какой, какой
     файл, коротким summary без содержимого секретов) в `raw_events`.
   - `SessionEnd` / `Stop` — схлопывает события сессии в одну запись
     `summaries` простым эвристическим способом (без LLM): список
     изменённых файлов, использованных команд, последний промпт пользователя.
   - `Setup`/health-check хук — не нужен на этом этапе (упрощение).

2. **Хранилище:** один SQLite-файл в `~/.claude-mem-lite/memory.db`
   (или per-project — обсудить с пользователем, см. п.6). Таблицы:
   `projects`, `sessions`, `raw_events`, `summaries` + FTS5-индекс по
   `summaries.text` для полнотекстового поиска.

3. **Поиск:** простой `mem-search` — либо slash-команда/skill в Claude Code,
   либо отдельный CLI (`npx claude-mem-lite search "запрос"`). Никакого MCP
   на этом этапе — избыточно для MVP.

4. **Приватность из коробки:**
   - тег `<private>...</private>` в промпте/выводе инструмента исключает
     контент из сохранения (как в оригинале, это хорошая идея);
   - список исключаемых путей (`.env`, `*.pem`, `id_rsa*` и т.п.) —
     никогда не логируется содержимое файлов из "чувствительных" паттернов;
   - переключатель `CLAUDE_MEM_LITE_ENABLED=false` и per-project
     `.claude-mem-lite/disabled` — можно выключить точечно.
   - **никакого сетевого вызова по умолчанию** — ни телеметрии, ни
     облачного аккаунта, ни LLM API. Всё работает офлайн.

## 3. Этап 2: сжатие через LLM (опционально, по явному согласию)

Только после того, как MVP работает и пользователь понимает, что именно
сохраняется:

- Хук `Stop` вызывает Anthropic API (ключ берётся из переменной окружения,
  которую задаёт сам пользователь — НЕ хранится в репозитории/плагине) для
  создания краткого семантического summary сессии вместо эвристического.
- Обязательно: явный флаг `CLAUDE_MEM_LITE_LLM_SUMMARY=true` — по умолчанию
  выключено, чтобы не тратить токены/деньги без согласия.
- Оценка стоимости: сессия ~= 1 короткий вызов модели (например,
  Claude Haiku) на завершение сессии — дёшево, но не бесплатно, это нужно
  явно сообщить пользователю в README.

---

## 4. Этап 3: MCP-сервер для умного поиска (опционально)

Если после MVP станет ясно, что простого CLI/skill недостаточно:

- Локальный MCP-сервер (stdio) с 2-3 инструментами: `search`, `recent`,
  `get_details_by_id` — по образцу progressive disclosure из оригинала
  (см. `src/server/mcp/recall-mcp-server.ts`), но без сетевого бэкенда —
  напрямую поверх локального SQLite.
- Никакого HTTP worker-процесса, никакого демона, слушающего порт — MCP
  stdio поднимается самим Claude Code по требованию, это проще и безопаснее
  (меньше поверхность атаки, нечего сканировать по сети).

## 5. Сознательно вырезано из оригинала (и почему)

| Фича оригинала | Решение | Причина |
|---|---|---|
| Облачный "observer" сервис с логином | Не делаем | Лишняя зависимость от стороннего сервиса и подписки, риск утечки данных проекта третьей стороне |
| Postgres backend, teams/api_keys/audit_log | Не делаем | Это инструмент для одного разработчика, мультитенантность не нужна |
| Chroma векторная БД | Отложено (этап 4, если понадобится) | FTS5 полнотекстового поиска обычно достаточно для персональной памяти |
| Поддержка 8 разных агентов (Codex, Cursor, Grok Bot...) | Только Claude Code | Экономия объёма работы, легко расширить позже |
| Крипто-токен CMEM | Категорически не делаем | Не относится к функциональности, репутационный и юридический риск |
| Обфусцированные однострочные bash-хуки | Читаемые Node-скрипты с комментариями | Прозрачность и безопасность — можно проверить, что именно исполняется |
| Автоматическая отправка данных куда-либо | Только локально, offline by default | Ключевое требование "безопасный аналог" |

## 6. Открытые вопросы к пользователю (нужно решить до кодинга)

Эти решения имеет смысл принять в начале сессии с Opus 5, а не в процессе:

1. **Область памяти:** одна общая база на все проекты или отдельная БД на
   каждый git-репозиторий (`.claude-mem-lite/` в корне проекта)? Второе
   безопаснее (нет утечки контекста между несвязанными проектами) и проще
   для git-игнора.
2. **Язык реализации:** чистый Node.js (без Bun, чтобы не требовать
   дополнительный рантайм) или Bun, как в оригинале? Рекомендация: Node.js —
   меньше системных требований для конечного пользователя.
3. **Нужен ли этап 2 (LLM-сжатие) сразу, или сначала обкатать
   эвристическое сжатие без вызовов модели?** Рекомендация: сначала без LLM.
4. **Формат распространения:** локальный плагин Claude Code (`.claude-plugin`
   + `hooks.json`) для личного использования, или публикация как отдельный
   npm-пакет для сообщества? Это влияет на то, насколько тщательно нужно
   документировать и тестировать edge cases.

## 8. Критерии "безопасности" аналога (проверочный список)

- Ничего не уходит в сеть без явного flag/согласия пользователя.
- Нет захардкоженных API-ключей, токенов, URL сторонних сервисов.
- Секреты (`.env`, приватные ключи, токены в diff) не попадают в БД.
- Весь код читаем (никаких one-liner обфускаций), можно аудировать перед
  установкой.
- Плагин можно полностью удалить: `rm -rf ~/.claude-mem-lite` +
  снятие хуков — не оставляет фоновых процессов/демонов.
- Нет крипто-токенов, платных подписок, апселлов внутри инструмента.
